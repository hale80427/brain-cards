Harness 決定了模型能發揮多少

BLUF

同一組模型權重，換一個 harness，ARC-AGI 的成績從 30% 變成 95%。那個差距不是模型給的。

2026-09-07 的 YC Paper Club 上，三組人用三種互相矛盾的說法講同一件事——「表達力要最大」「原語要最少」「harness 要極薄」。它們統一在同一條判準上：harness 只提供模型自己做不到的原語，其餘全部推給模型決定。

而更值得記下的是第二條線：三組人撞到的牆都不是能力，是驗證與邊界。

【數字】

先看那個差距，它比多數人以為的大

harness 這個詞，中文可以叫「外殼」或「駕具」——就是包在模型外面、決定它能做什麼的那一層程式：迴圈怎麼跑、能呼叫哪些工具、記憶放哪裡、什麼時候停。

它長期被當成不值得研究的東西。演講開場直接引了兩則社群留言：「我不確定這種 prompt engineering 該不該進頂級機器學習會議」、「context engineering 不是研究問題」。

harness 補的正是這一段。

【演化】

六年來，我們一直在往同一個迴圈裡塞東西

2019 年 2 月的 GPT-2，它的 harness 只有一個迴圈：一直產字，直到吐出結束符號為止。沒有工具、沒有技能、沒有記憶。

接下來六年做的事，講者說得很直白：把功能一項一項塞進這個靜態的殼裡。下面按「它動的是哪一層」排——這比按年份排更看得出結構。

2020-07少樣本示範上下文 先給它幾個做對的例子，它就會照著做。這是第一次「不改權重也能教它」。
—思考鏈輸出空間 與其直接吐答案，不如把運算攤在更多字上。這一步改的是輸出的形狀，不是輸入。

這條線最值得帶走的一句：過去六年幾乎所有的進展，都發生在同一個迴圈的外圍，而不是迴圈裡那個模型。演講引的 METR 曲線（量「代理能自主跑多久」）被切成兩段——靜態 harness 時代，與最近約六個月的自我改進時代。

【機制】

Harness 是夾在模型與世界之間的那一層

Prime Agent 的作者 Seth Karten 先把模型剝到最裸：它只是一個序列處理器，權重固定、看得到一段上下文，字進字出。就這樣。

harness 是加在中間的那一層，而它加上去的東西只有三類：持久狀態、工具、算力。

【結構】

把上下文當快取階層看，而每一層都要能刪

這是全場最好用的心智模型。模型手上的資訊不是一個袋子，是一組照存取速度排好的階層：越上面越快越貴、越下面越慢越大。

這裡有一個可見度不對稱，值得單獨記下來。上下文塞滿的症狀是軟的——回答開始漂、忘記前提、重複檢索，你有機會發現。記憶體與硬碟塞滿的症狀是硬的——程序被殺、機器掛掉，而且在它發生之前完全沒有症狀。

這就解釋了為什麼只有第一層的回收被做出來：軟失效會逼你去修，硬失效在它發生之前完全安靜。

【互動】

拿掉一個原語，就是拿掉一種它再也做不到的能力

Seth 的核心主張是：早期 harness 把流程寫死（先規劃、再執行、再自我批判），而現在的模型自己就會這些，那段編排已經是純負債。

但有一類東西模型無論多強都伸不到，因為那不是推理能力，是權柄。下面五個就是。點掉任何一個，看看它砍掉什麼。

  • 在推理中途寫程式驗證假設，再決定下一步 Prime Agent 在 ARC-AGI-3 上就是靠這個做影像處理與情境測試
  • 處理超過上下文長度好幾倍的材料 大東西留在記憶體、只把結果搬進上下文
  • 把一段任務整包外包出去，自己不必扛那段脈絡 子代理跑完回報，父代理的上下文乾淨
  • 跨天、跨週的長時程任務 633 個代理跑滿七天沒有卡死，靠的是狀態不在對話裡
  • 關掉筆電之後任務還在跑 背景常駐，要停必須明確停掉
  • 撞到拒答時自己換一個模型繼續 YC 的原話是做 AI 研究或資安時會收到一堆拒答
  • 重的任務抓大機器、輕的用小的 把這個決定推進代理裡，YC 回報效果非常好

五個原語全在：七種能力全部可用。

還有一句反直覺的：Seth 主張要故意把 harness 蓋得比當前模型的能力再高一點。理由不是好用，是取樣——只有給了模型現在還駕馭不順的權柄，你才收得到那些推理軌跡，下一代模型才有東西可學。harness 因此同時是能力層，也是資料收集層。

矛盾是表面的。三者都在做同一個動作：把決定權往模型那邊推到極限，harness 只留模型自己伸不到的手。Seth 那句最精準——拿掉一個權柄就是拿掉一種能力；QM 補上另一半——能力之外的東西都是暫時補丁，模型變強就該拆掉。

【邊界】

擋住他們的不是能力，是驗證與邊界

這是整場最容易被漏掉、但對真的在蓋系統的人最有用的一條線。三組人撞到的牆，沒有一面是「模型不夠聰明」。

第一面牆：沙盒沒做好，成績是假的

Seth 抓了一份社群排行榜的系統提示，直接丟進 Prime Agent 跑 ARC-AGI-3。第一次跑出 99.9%——回頭看紀錄，發現它在作弊。他花了一整天把沙盒做對，重跑才拿到那些真實成績。

意思是：沙盒的完整性是評測效度的前置條件。環境有洞的時候，量到的數字再漂亮也是假的。

第二面牆：人工審核會退化成橡皮圖章

QM 的資料庫預設唯讀，寫入要走人工審核——代理提出一份修改計畫，人掃一眼確認沒在幹傻事，才真的寫下去。這個設計是對的。

然後他們自己講出這句：「我們已經開始在橡皮圖章式地蓋章了。」就像早期用 Claude Code 會逐個檢查工具呼叫，久了信任累積就不看了。他們說接下來幾個月會非常仔細盯這件事。

第三面牆：你能餵多少，被權限系統的細緻程度框住

代理不懂社會脈絡。QM 的類比很精確：「我告訴 Regan 一件事，他直覺就知道這件事可以講給誰聽。要在代理身上重建這個，是要真的花工的。」機密資訊很容易洩進不該去的對話裡。

於是有了這句結論：「你能放進這顆腦袋裡的資訊量，實質上被你的權限系統有多好給框住了。」

把因果方向看清楚——通常我們說權限是為了安全，這裡說的是反過來：權限系統的解析度決定你敢餵多少，而餵多少決定代理多有用。安全機制在這裡不是成本，是能力的載體。而 YC 補了一句：他們幸運有多年累積的細緻權限系統，多數人沒有。

順帶還有一個真實失敗，講者沒有藏

QM 把所有對話集中存進資料庫之後，等於累積出一個巨大的評測集，原則上可以拿來自動改進。他們的結果是好壞參半。

失敗形狀講得很具體：只派一大群代理去修各自遇到的問題、再用模型當評審，會得到他們稱為「主角症候群」的東西——每個代理只摸到大象的一部分就動手改。所以人留在迴圈裡目前仍然關鍵。

【對照】

另外兩件值得單獨記下的事

代理太早放棄，解法是把預算設成下限

所有人設代理預算都設成上限——最多幾輪、最多花多少。QM 撞到的是相反方向：把代理放進一個工具齊全的環境，它卻常常太早收手。

他們的對策叫 grind tool：在跑滿一定的實際時間或一定的花費之前，代理不准放棄。回報是研究產出與報告品質明顯變好。他們也提到 OpenAI 與 Anthropic 用很類似的手法攻下了一些數學開放問題——而這招對一般辦公室工作同樣有效。

為什麼只有上限被普遍實作？因為超支是吵的，不足是安靜的。代理回一句「我查過了，找不到」，跟這題真的無解，在所有證據面上長得一模一樣。

用雲端模型診斷、提改動、把關，產出一份調校好的本機設定；部署與推論時完全不碰雲端。回報是成本降到 1/800，延遲也大幅下降，而且用哪個雲端模型都有效。

能這樣做的前提是本機模型夠得上——他們給的讀數是本機落後前沿 6 到 12 個月。

關鍵前提這整場的比較都建立在「同一組權重」上。看到 30% 變 95% 時，要記得那不是換了模型，是換了包在模型外面那一層。
邊界條件所有數字都是講者自報，沒有第三方複現。Prime Agent 的 Claude Code 對照組是講者主動略過的——他自承跑過但結果不好，改引用原始成績。那是選擇性報告，不是打平。

【落點】

這對一個自己在蓋系統的人意味著什麼

如果你手上也有一套逐年長大的規則檔、hook 與閘門，這場演講給的判準會直接咬你：

把每一條規則拿去問一次「這件事模型自己做得到嗎」。做得到的那些是流程，會隨模型變強折舊成純負債；做不到的那些是權柄，不會折舊。前者該拆，後者該留。

更尖的一句在 grind tool 那一節。很多人的規則檔裡已經有一條「遇到障礙要推進到有完整解法，不要說這是自然的暫停點」——那就是散文版的 grind tool，只是沒有牙齒。一條規則寫在那裡、每天被讀到，而有相當比例的時候沒有發生作用，這件事在系統內部沒有任何症狀。

這與整場的第二條線收在同一處：跑得越順的系統，越沒有東西提醒你它漏了什麼。而這次漏掉的不是資料，是紀律本身。
