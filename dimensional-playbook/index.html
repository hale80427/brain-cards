立體化敘事怎麼用才會成功

BLUF

這三輪真正改變的不是畫圖技術，是把「立體」拆成兩個彼此獨立的問題。舊流程只問一個：這張圖要不要第三個資訊維度。新流程答完之後再問第二個：這張圖要不要有體積感。前一份交付之所以九條判準全過還是被判失敗，就是因為系統只驗了第一個問題，而要的是第二個。

追問之後排除了兩個技術假說：圖有 render 出來，而且他滑到了。他選的是第三個——滑下去有圖，但那不是我要的立體。

這句話值得記下來 缺的不是可讀性。可讀性已經達標了，是第三方盲讀證明的。 問題出在「立體」這個詞被翻譯成一個可驗的定義之後，那個定義就把原詞頂掉了。之後每一道閘都對著新定義跑，全綠只證明新定義被滿足。而翻譯這件事本身不留任何痕跡。
改了什麼

判準從一層變成兩層，而兩層的答案可以不同

舊判準只有一句話：我要讀者從這張圖讀出一個數字嗎？要，就不准立體。

那句話沒有錯，但它只管一件事：資訊有幾個維度。它從來沒問畫面有沒有體積感。

視覺深度長什麼樣

三個要素：兩個以上的面、面與面之間的明暗差、沒有刻度

三種手法

三種都保留，因為它們在不同的地方會壞

三種立體手法的對照，含各自的失效面
手法關掉 JavaScript什麼時候用代價
SVG 等角實體圖照樣在物件本身有體積，而你只要讀者看懂形狀。目前的預設。旋轉對稱體在等角下不會自我遮擋，所以它給的是體積感、不是新資訊。
CSS 3D 分層圖照樣在幾個階段沿深度排開、前面的擋住後面的。形狀語言與另外兩種不同，換題材時要重想「那一層是什麼」。
canvas 手寫投影加拖曳圖全沒了讀者真的需要繞著看才用。與整份頁面空白是同一個失效面；而且強制轉鏡的迷向在文獻上顯著更高。

三種都保留是使用者拍板的，理由是不同場景會需要不同的一種。參考實作與四個踩坑寫在同一份 KB 裡。

怎麼觸發

四個動作，前兩個決定會不會走到判準，後兩個決定品質

一　走 /output-html，不要直發前一份失敗品走的是直發通道，七道閘一道都沒經過。這是最便宜的一個動作。
二　逐節問兩句這一節要解釋一個結構或機制嗎？是的話，這個結構是三維實體嗎？兩句都答是才進判準。
三　兩層各答一次要讀出數字嗎？要體積感嗎？兩個答案可以不同，而且要在文中寫出為什麼這張立體、那張平面。
四　三重驗收缺一不可七道機器閘、把圖裁出來放大親眼看、派一票盲讀。最後你自己在手機上開。

什麼時候不要用

三種情況直接跳過，不要硬套。

第一，讀者要從圖上讀出數值或比相對位置。深度線索在文獻上會讓這類判斷變差。

第二，題材裡沒有可畫的實體。純財務、純合約、純論證結構硬套會做出假的解剖圖，而那會讓主張看起來比證據整齊。

第三，讀者不需要繞著看。那就不要用會在關掉 JavaScript 之後整個消失的那一種。

誠實邊界

這份手冊的證據強度到哪裡為止

第一，第二層判準的全部證據，就是一個人在一次四格並排實驗裡的一句話。第一層有三篇文獻，第二層零篇。

第二，那次並排實驗有做防呆：第四格與第一格的原始碼逐字相同，他選了第一格而且沒有宣稱兩者有差別，所以這個讀數可以解讀。

第三，但位置效應沒有排除。他選的那格是第一個選項，而過去的實測是八次並排選擇有七次選第一個。唯一削弱這個疑慮的，是他答案裡有一句位置效應產不出來的話：「以這個場景來說」。那是論證，不是證據。

第四，「他要視覺深度」不等於「視覺深度讓他讀得更準」。這一層買到的是他願意讀，不是他理解得更好。後者在文獻上有反證。
