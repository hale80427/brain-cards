垂直 AI 產品的形狀

從 Anthropic SMB 公告拆解到漢鼎超音波加工 Agent 設計｜6 條結構性原則 + v1.0 設計含意

BLUF

Anthropic 2026 年 5 月推出 Claude for Small Business，把通用 Claude 包裝成中小企業專用的垂直產品。本文不討論產品本身好不好用，而是拆解它的設計骨架——共 6 條結構性原則。每條原則都附對漢鼎自建超音波輔助加工 Plugin / AI Agent 的設計含意。

結論：v1.0 不需要訓練新模型、不需要做開放 SDK；先盤點漢鼎內部過去 1–2 年的 Top 10 高頻加工場景，按「ready-to-run workflow + 可重複動作 skill + 業務鏈關鍵接口 integration」這三層組合來設計。

為什麼拆這個？

當模型能力越來越像公共基礎設施（GPT-4、Claude、Gemini 之間的差距收斂到 10% 以內），下一輪 AI 產品的差異化價值會放哪？Anthropic 對中小企業（Small Business，SMB）的這套打包提供一個正在進行的實證。

我們不關心這個產品在美國的銷售表現，而是它的設計骨架——因為這套骨架可以被遷移到漢鼎自建的「超音波輔助加工 AI Agent」場景，作為設計參考依據。

本文範圍：討論「形狀」（產品該長什麼樣），不討論「該不該做」（商業可行性、投資報酬率等決策層問題）。

原則 1：差異化在組合層，不在模型層

別想著訓練新模型，把「預配劇本 + 可重複動作 + 領域接口」這三層組合做好。

為什麼是這樣？

Anthropic 推出 Claude for Small Business 時，底層用的還是原本的 Claude（公告完全沒提任何新模型），組合結構是「15 個立即可用的劇本（workflow）+ 15 個重複動作（skill）+ 7 個業務整合（integration）+ 新平台 Claude Cowork」。

這個事實本身就是訊號——當中小企業採用 AI 的真正瓶頸是「通用工具沒有為他們的工作方式客製」（Anthropic 自己的論述），垂直化的價值就必然從模型層位移到組合層。

對漢鼎的設計含意

未來自建超音波加工 Plugin 不需要重新訓練模型，應該設計三層：

  • 多步劇本（workflow）：N 個典型加工場景的整套流程（例如 Al-SiC 蓋板從粗加工到精磨的全流程）
  • 重複動作（skill）：Y 個經常觸發的單步技能（例如給定材料硬度與目標粗糙度計算超音波振幅與進給量、振動頻譜異常分類、刀具磨耗補償）
  • 業務接口（integration）：Z 個製造業關鍵整合（CAM 軟體輸出、機台 OPC-UA 協定、振動感測器 API、品質管理系統記錄回寫）

差異化價值不來自「比 ChatGPT 更會回答機械工程問題」，而來自這三層的縫合品質。

原則 2：批准閘門設在「動作即將產生不可逆後果」之前

別把人工確認設在任務做完才看（風險都放掉了），也別每句話都問（會把使用者卡死）；設在「東西即將寄出 / 發佈 / 付款 / 動機台」這個顆粒度。

為什麼是這樣？

Anthropic 在公告把這條紀律寫得很直接：每個任務都由使用者啟動；可以先批准計畫，或在熟悉後一鍵跑完；Claude 做事，但任何「寄出、發佈、付款」之前都要使用者批准。

關鍵在「寄出、發佈、付款」這三個動詞——共通結構是「動作完成後狀態無法回收」。批准閘門（approval gate）設在這個顆粒度同時承擔兩個獨立功能：

  • 風險過濾：避免 agent 失誤造成外部損失
  • 責任邊界：讓人類保有最後決策權，避免法律與信任問題

對漢鼎的設計含意

超音波加工有強烈的物理不可逆性，閘門顆粒度必須比 SMB 場景更嚴格：

動作類別不可逆性批准顆粒度
製程參數計算、報表草稿、分析摘要低（純內部運算）end-to-end 可（一鍵跑完）
工件加工程式輸出、夾具參數修改中（送出到 CAM/CAD 即生效）必須批准計畫
機台執行指令、刀具退刀路徑、振幅調整高（直接控制物理動作、機械破壞風險）必須逐筆批准 + PLC 硬迴路兜底

原則 3：Workflow 與 Skill 是劇本與技能的關係

劇本管「多步業務流程怎麼一條一條接起來」，技能管「單步動作怎麼穩定做到」；同一個技能可以被多個劇本共用。

為什麼是這樣？

Anthropic 在公告把這條職責切分寫得很清楚：15 個「立即可用的多步劇本」加上 15 個「以重複動作為基礎的技能」。兩個關鍵形容詞揭露結構——workflow 是多步、有編排、可一鍵啟動，skill 是單步、可重複、是動作而非流程。

為什麼要切兩層？若全部做成 workflow，產品變成 N 條無法組合的長劇本，每個新需求都要新建一條；若全部做成 skill，使用者必須自己編排步驟順序，等於把縫合成本退回給客戶。

兩層結構讓供應商承擔「業務流程怎麼跑」的設計責任（這是垂直化的核心價值），同時讓客戶能在 workflow 之外用 skill 處理零散需求。

對漢鼎的設計含意

層級範例
Workflow（多步劇本）「新訂單→製程設計→參數計算→刀具規劃→試切驗證→量產執行→品質回饋」全流程
Skill（單步可重複動作）「給定材料硬度與目標粗糙度計算振幅與進給量」、「振動頻譜異常分類」、「刀具磨耗補償」、「批次良率歸因」

同一個 skill「計算振幅與進給量」可以被「新製程開發 workflow」、「客戶投訴歸因 workflow」、「品質改善 workflow」三條不同劇本共用。Skill 設計時追求單一動作的職責純度（純函數性質：相同輸入產生相同輸出），workflow 設計時追求業務流程的完整覆蓋。

原則 4：整合按業務動詞選，不按客戶現有 SaaS 選

別追求「客戶用什麼工具我都接」（會把整合成本擴散到無限長尾），追求「業務鏈的關鍵動作各被覆蓋到一個」。

為什麼是這樣？

Anthropic 在 Claude for Small Business 只選了 7 個整合，每個都直接對應業務鏈的關鍵動詞，沒有整合 Salesforce、Slack、Shopify、Stripe、Notion 等其他常見 SMB SaaS。這個取捨揭露了選擇邏輯——

整合業務動詞
QuickBooks記帳（薪資、月結、現金流、稅季）
PayPal收款（結算、發票、爭議、退款）
HubSpot行銷銷售（線索分流、客戶脈動、活動歸因）
Canva內容生產（多通路內容、發佈、追蹤）
Docusign合約簽署（送簽、追蹤、歸檔）
Google Workspace / Microsoft 365基礎協作（文件與通訊）

7 個整合分別佔據了 SMB 業務鏈的 6 個關鍵動作節點，每個節點選最大覆蓋率的工具。整合的真正價值不是「客戶不用切換工具」，而是「業務動作可以被 AI 跨工具串成 workflow」——例如薪資 skill 同時用 QuickBooks 與 PayPal 兩個整合。

對漢鼎的設計含意

應按精密加工的業務鏈盤關鍵動作節點：

業務動詞候選整合
製程設計CAM 軟體（Mastercam / NX CAM 擇一最大覆蓋）
參數計算內部技能庫 + 振動感測器即時數據 API
機台執行OPC-UA / MTConnect（標準協定優先於品牌 API）
品質回饋QMS（漢鼎內部系統優先於第三方）
記錄與追溯ERP（鼎新 / SAP 擇一）
客戶溝通Email / LINE（基礎協作）

v1.0 不應追求「整合全部客戶現有工具」，而應每個動詞節點選一個最大覆蓋率的接口。若某客戶用的工具不在預設清單，提供「資料匯入/匯出 CSV」這條退一步接口即可。

原則 5：市場敘事的三段論母骨架

對外論述用「客群規模大 + AI 採用落後 + 通用工具沒為他們客製」這三段，每段補另兩段的弱點，形成自洽閉環。

為什麼是這樣？

Anthropic 在公告把這條三段論寫得非常工整：中小企業佔美國 GDP 的 44%、雇用近半的私部門勞動力；但他們採用 AI 的速度落後於大型企業；因為工具和訓練很少為小企業的工作方式客製。

逐段拆——

  • 規模證明（44% GDP + 雇用近半勞動力）：先建立「這個客群值得單獨服務」的前提
  • 落後證明（採用落後大型企業）：把客群放在「需要被解救」的位置
  • 歸因（工具未為他們客製）：把落後原因歸到供給方沒做，而非客群自己不行——這條歸因方向關鍵在於它同時保留客群尊嚴並創造供給方的進場理由

三段合在一起每段補另兩段的弱點：若只有規模證明會被質疑「為什麼現在才做」、只有落後證明會被質疑「是不是客群本身有問題」、只有歸因會被質疑「真的有市場嗎」。

對漢鼎的設計含意

可套用這個敘事骨架建立進場論述：

段候選論據
規模證明「精密加工佔台灣製造業 GDP X%、雇用 Y 萬名工程師與技師」
具體數字需查經濟部統計處 / 工研院 IEK
落後證明「中小型精密加工廠 AI 採用率遠低於半導體大廠 / 電子代工大廠」
需查工研院 AI 採用調查
歸因「通用 AI 工具的訓練資料不含小批量精密加工的隱性 know-how、CAM 操作邏輯與機台特性，無法直接解決機械工程師的日常問題」
注意：具體數字必須查證後填入，不能直接套用 Anthropic 的 44%。

原則 6：MVP 階段給足預設模板，不開放高度自訂

對非技術型使用者，「選擇成本」本身是進入障礙；給 30 個立即可用的模板，比給 SDK 讓他們自己組更能跨過冷啟動。

為什麼是這樣？

Anthropic 在 Claude for Small Business 完全沒提 customization、extend、build your own、custom workflow、SDK 任何字眼，只強調 15 個 ready-to-run workflow 加上 15 個 skill 這兩個固定數字。

這個事實本身就是設計取捨的物質證據——MVP 階段選擇「給足預設」而非「開放自訂」。

為什麼這樣選？對中小企業主而言「選擇成本」本身是進入障礙。SMB 業主每天面對的決策遠超過注意力預算（接單、人事、財務、客戶），任何需要他們「先選好、再學會、再組裝」的工具會被優先放棄。

若 Anthropic 一開始就推「Claude Cowork SDK，自己組 workflow」，需要的使用者素養是「能定義自己的業務流程 + 能用 prompt 描述步驟 + 能 debug」——這套素養門檻會把 99% 的目標客群擋在門外。

反過來，給 30 個 ready-to-run 模板讓使用者「選一個按下去」，需要的素養只有「能辨認哪個模板貼近自己的場景」，門檻接近零。

對漢鼎的設計含意

v1.0 不應做「框架式」（讓機械工程師自己組裝振幅、進給量、刀具補償的計算流程），而應預配 N 個典型加工場景的整套流程：

預設場景候選整套流程
Al-SiC 蓋板粗加工材料識別 → 振幅範圍 → 刀具選擇 → 進給量 → 試切驗證 → 量產參數
碳化鎢精磨砂輪選擇 → 振幅 → 進給速度 → 表面粗糙度檢測 → 補償循環
鋁合金薄壁件變形預測 → 切削策略 → 振幅 → 夾持方案 → 量測點規劃
客戶投訴歸因取樣 → 振動譜分析 → 參數回溯 → 製程問題定位 → 改善建議

預設場景的選法：盤點漢鼎內部過去 1–2 年實際接過的訂單，找出 Top 10 重複出現的場景。覆蓋率 80% 即可，剩下 20% 留給「自由提問」這條退一步接口。

結論：漢鼎超音波加工 Plugin v1.0 的設計路徑

把 6 條原則合在一起，會浮現一條更上位的設計骨架——垂直 AI 產品的完整形狀由三組權衡構成：

  • 組合層 vs 模型層（差異化價值放哪）
  • Workflow 與 Skill 的職責切分 vs 單層平鋪（內部結構長怎樣）
  • 預設模板覆蓋率 vs 客製化彈性（起步門檻擺哪）

三組權衡都偏向「組合 + 兩層切分 + 預設多」這個方向是有原因的——這個組合最能在「目標客群是非技術型使用者」這個前提下同時達成最低起步門檻與最高縫合密度。

對漢鼎超音波加工 Plugin v1.0 的具體含意：
  1. 不需要訓練專用模型、不需要做框架式 SDK
  2. 先盤點漢鼎內部過去 1–2 年實際接過的 Top 10 高頻加工場景
  3. 把每個場景的整套流程預配成 ready-to-run workflow
  4. 把流程內的重複動作（振幅計算、刀具補償、頻譜分類）抽成 skill
  5. 整合層按「製程設計→執行→品質→記錄」這條業務鏈各覆蓋一個接口
  6. 批准閘門設在「動作即將產生不可逆物理後果」這個顆粒度

三層做好了，差異化價值會自然發生在組合層。這條路徑與 Anthropic 在 SMB 市場走的路徑同構，只是領域從財會、行銷、合約位移到製程、機台、品質。
