為什麼跟 Claude 講話會越用越便宜——影印店常客資料夾的比喻

BLUF

跟 AI 對話時，系統會把「不變的部分」存進類似「影印店常客資料夾」的快取（cache）。第一次建檔貴一點，之後每次只要付 1/10 的影印費。

我過去 19 天的快取命中率（hit rate）是 93.74%，每月省約 3,000 美元。

而這個省下來的錢不是因為我有什麼厲害的技巧——是因為我「不亂動設定」。

一、把 Prompt Cache 翻成人話

想像你常跑同一家影印店。每次去都帶一疊資料：

  • 常客資料夾：公司簡介、規格表、報價單（內容大部分不變）
  • 今天要印的新文件（這次的問題）

系統設定（system prompt）、~/.claude/CLAUDE.md、Skills 描述、歷史對話，都是「常客資料夾」。當次提問才是「新文件」。

技術名詞翻譯收費
Cache write（建檔）第一次帶資料去店裡、店員幫你影印留底比正常價貴一點
Cache read（翻檔）之後每次來、店員只看資料夾 + 新文件前 99 頁費用降到 1/10
Uncached input完全沒進資料夾、每次重算最貴

Hit rate 命中率 = 翻檔次數佔總輸入的比例。Anthropic 文件建議 ≥ 70% 算健康。

二、實測數字長什麼樣？

直接看我過去 19 天的數字：

  • cache_read_input_tokens（從常客資料夾讀的）：7.72 億 tokens
  • cache_creation_input_tokens（第一次建檔費）：5,150 萬 tokens
  • input_tokens uncached（沒進資料夾、每次重算）：7.2 萬 tokens

「從資料夾讀的」佔了 93.74%。

註：token 是模型計費的最小單位，約等於 0.75 個中文字或 1 個英文音節。

三、為什麼我可以打到 93.74%？

四個結構性原因，都不是技巧、是紀律：

  1. ~/.claude/CLAUDE.md 寫得短而穩定——150 行、沒事不改 → 快取一直命中
  2. Skills 的觸發詞與描述不亂動——載入 skill 表也吃快取
  3. 每段對話（session）都很長——前 100–900 條訊息的快取累積效益巨大
  4. 不在對話中途切模型（沒有 mid-session Sonnet → Opus 的習慣）→ 快取結構穩定

四、如果做反方向會怎樣？

動作後果
每天改 CLAUDE.md 幾行cache_creation 變主流、貴 2 倍
每件小事開新 session 講 2 句就 /clear快取永遠在重建、吃不到便宜
對話中途切換模型快取全失效、從零開始

這三個動作都是「為了更好」做的——更新規則、保持乾淨、選用更強模型。但每一個都會打掉快取。穩定本身就是一種優化。

五、月省金額換算

過去 19 天 8.22 億 input tokens：

  • 實付：$540 USD
  • 若無 cache：$2,471 USD
  • 省下：$1,930 USD（78%）

按比例外推 → 每月省約 $3,000 USD（若維持當前用量）。

六、我要做什麼？

簡單三條：

  1. 維持現狀——不為了多 5% 改結構
  2. ~/.claude/scripts/measure-cache.sh 每月跑一次當體檢
  3. 體檢門檻設 80%（而非文件建議的 70%）——掉到 80% 才需追根因

為什麼門檻不用文件預設的 70%？因為我的基準是 93.74%。掉到 80% 已經是「相對自身基準的明顯衰退」，不是「最低及格」。

監控指標的閾值應該以自身歷史基準正負偏移設定，而非套用通用建議值。這條延伸到所有監控（延遲、錯誤率、留存率）都適用。

三個關鍵洞見

Cache 是「穩定性的紅利」

你越不亂動 CLAUDE.md / Skills / 模型選擇，cache 越省。我現有架構穩定到讓 cache 接近理論上限（93.74%）。

這是「克制 + 不過度優化」的回饋，不是技術技巧的回饋。

影印店比喻可重用

「影印店常客資料夾」適合解釋給任何不熟 LLM 內部結構的人聽（家人、客戶、同事）。

比直接講 cache_read / cache_write 容易理解 10 倍。

且不犧牲技術正確性——build 真的是貴 2 倍、read 真的是便宜 1/10。

不要為了多 5% 改結構

當主要指標已接近上限，任何結構變動都是「邊際收益 vs 破壞穩定」的賭注，預設答案應為「不動」。

架構優化的盡頭是穩定性，不是技術新潮。
