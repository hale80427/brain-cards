2026 年 5 月 27 日 · 一個關於工作習慣的問題

我問了我的第二大腦一個問題：以前的工作流還需要嗎？

一句話結論

我那套跟了好幾年、手動寫 Prompt 的老工作流，不該繼續當預設流程——但它也沒有消失。它被升級成了我個人作業系統內部的子程序。第二大腦給出兩條結構性命題，順便指出下一波介面層躍升該往哪裡看。

一個跟了我好幾年的老習慣

有一個習慣我跟了好幾年。每次想用 AI 做點正經事，我會先跟它討論一輪——這個任務的目標是什麼、什麼算做完、哪些雷不能踩、要用什麼結構輸出。

討論完，我把這些條件壓成一段「Prompt」（給 AI 的開場指令），然後開一個新對話視窗，把那段 Prompt 貼進去，正式開工。

這套習慣在 2024 年還很合理。當時 AI 助手沒有記憶、沒有預先設好的工作模板、沒有跨對話的協作機制。你不替它做這些準備，它就會把每件事做得很差。

但今天，我自己花了 14 個月在 Claude Code 上面建了一整套個人作業系統。

有負責找資料的，有負責檢查 AI 味的，有負責做 HTML 的，有負責跨領域對照的，有負責記住前幾次對話的。光是最近兩天，我才跑完一輪 AI 評估工具的三次升級，加上整套子代理人協作協議的補強。

那這套老習慣，還需要嗎？

我的第二大腦回答：兩條結構性命題

我把問題丟給自己的第二大腦，請它從累積的 900 多張命題卡片裡找答案。它沒有停在「該不該繼續」這層，而是把問題翻成兩條更深的觀察。

母線 A：成熟的訊號是「手動動作消失」，不是「功能變多」

第一條命題是這樣的：你要判斷自己的個人 AI 操作系統有沒有成熟，真正能用的標準不是 skill 的數量、不是記憶的容量、不是條目的多寡。

是原本要自己手動做的準備工作，是不是已經被系統自動完成了。

這些表面數字都會誤導人。真正的骨架訊號是：「我還在哪些動作上自己手動準備？」那些動作，就是系統還缺對應 skill 的位置。

換個直覺類比

判斷一個程式函式庫成不成熟，不是看它有多少函式、文件多厚，是看你寫程式時還要重複貼幾次套版程式碼。套版還沒消失，那個位置就是函式庫沒覆蓋到。

判斷一個工廠製程穩不穩，不是看廠房多新、設備多貴，是看現場師傅每批還要不要手動微調機器。手動還在發生，那個位置就是製程窗口沒鎖好。

判斷一個團隊成不成熟，不是看 SOP 寫多厚，是看跨部門協調動作有沒有消失。協調還在大量發生，那個位置就是平台沒做出來。

骨架是一樣的——成熟度看的是手動動作有沒有消失，不是看擁有多少功能。

回到我自己的工作流

我把舊工作流的四個動作對應到 OS 已內建的功能：

我以前手動做的 OS 已經幫我做了
外面跟 AI 討論目標 second-brain skill 的查詢與 brainstorming 流程
列出驗收標準 每個 skill 開頭預先寫好的觸發條件與檢查清單
寫 Prompt 指令 skill 本體 + 子代理人協議三件套
開新對話視窗執行 子代理人的乾淨脈絡隔離

四個動作都已經內建。我繼續手動跑一遍，等於是在已經有洗碗機的廚房堅持用手洗。

反過來說——什麼時候該手動？

如果某個任務不在我現有 skill 任何一個的觸發範圍裡，那個任務值得手動準備一次。但那次手動準備的目的，不是「再做一次」。

而是把這次的手動動作寫成新的 skill 然後存進去，下次同類任務就不用再手動了。

這也是我這兩天做的事。AI 評估工具升了三版、子代理人協議補了兩條實戰規則——本質都是把「我手動踩過的坑」變成系統會自動避開的規則。失敗模式被記下變成規則，比 debug 完拍拍灰更有價值。

母線 B：介面層升級的三段定律

第二條命題更底層一點。第二大腦把它寫成一句短話：

介面層每升一段，前一段的手動動作就會被內建為子程序。

什麼叫「介面層」？把人類跟 AI 互動的歷史拆成三段就清楚了。

第一段：指令層（2022 – 2024）

這是 Prompt Engineering 時代。人類手動構築對話脈絡、定義目標、寫好指令、檢查輸出。每個任務都是一次性。我那套老工作流就是這層的典型例子。

第二段：外骨骼層（2024 – 2025）

這是 Harness Engineering 時代。Cursor、Aider、LangChain 這些工具出現，把「每次都要重寫一遍指令」這個手動動作打包成可重複的工作流。第一段的手動準備被內建成函式呼叫鏈。

但這層仍有手動成分——使用者要決定用哪個 harness、要手動切換工具、要自己管理多個工作流之間的脈絡。

第三段：作業系統層（2025 – 2026 的現在）

這是 Claude Code 的 skill 系統，加上記憶系統、加上子代理人協議組成的層。它把「手動挑哪個外骨骼工具」這個動作也內建。

我說「請讀取我的第二大腦」這句話，系統就會自動進入查詢模式、自動載入 Vault 控制層、自動準備工作環境。我已經不需要決定「現在該用哪個工作流」。

規律是什麼？

每升一段，前一段的手動動作就會被新層當作子程序自動執行。

注意「自動執行」這幾個字——舊動作沒有消失，只是執行位置從使用者轉移到系統。

Prompt Engineering 不會過時，它只是從「使用者技能」變成「系統設計者技能」。掌握底層的人，在每一波介面層升級裡會繼續享有優勢。

這條規律能用來預測下一波

下一波躍升何時來、會躍到哪去，我們可以從「現在 OS 層還剩哪些手動動作」推測。目前我在 OS 層還在手動做的事情：

  • 我還在打 /second-brain 觸發 skill。下一代可能變成自動偵測語言訊號直接跑
  • 我還在手動決定要不要切 worktree、要不要 dispatch sub-agent。下一代可能變成 OS 自動判斷任務隔離需求
  • 我還在手動跨 OS 做工作分流（Claude Code 配 ChatGPT 配 Codex 配 Hermes）。下一代可能是組織級的代理人協作層

哪些動作還沒消失，那裡就是下一波介面升級的待開發空間。

兩條母線合起來說了什麼？

它們沒有說「以後可以不寫 Prompt」。指令工程不會消失，只是被升級了使用者。

它們沒有說「OS 越多 skill 越好」。成熟度的指標是「哪些動作消失」，不是「擁有多少」。一個 skill 數量不多但精準覆蓋日常準備動作的 OS，比一堆 skill 但仍需手動切換的 OS 更成熟。

它們真正給的，是一條很實用的判準：仔細觀察自己最近一週還在哪些動作上做手動準備，那就是下一張 skill 該蓋的地方。

至於我自己那套跟了好幾年的老工作流——它沒有消失。它被升級成了我 OS 內部的子程序。它仍在跑，只是不再由我手動執行。

附註：這兩條命題已寫成 evergreen Card 收進第二大腦 Vault，掛在「MOC AI 工作流條件設計與收斂控制」之下。

寫卡過程本身就是這條規律的小型示範——SYNTHESIZE 對話把「跨多卡的同構觀察」這個動作，從手動推導內建為 skill 路由的自動產出。
