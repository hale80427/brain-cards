教 AI 不要做出「一看就 AI 做的」網頁

BLUF

AI 寫出來的網頁有種共同氣味——紫色漸層當背景、Inter 字體當 hero 標題、滿版置中的大字、底下三欄 feature 卡。我今天接入了一個叫 hallmark（品質印記）的工具來擋這套樣板，把它編進我的 HTML 輸出流程，再把規則下沉到模板裡——讓 Claude Code 主流程跟 Telegram 機器人兩條通路一次受惠。

為什麼 AI 做的網頁長得都一樣？

讓 AI 寫網頁這件事已經很常見。但只要看多了會發現，它們的長相有點像。

背景常常是紫色漸層。標題字體永遠選 Inter（一種設計師常用的英文字體）。Hero（網頁頂端的大圖區）必定置中。下面接三欄 feature 卡，每欄一個 icon 加一句話。

這不是巧合。AI 在訓練時看過幾百萬個網站，它學到的「網頁應該長什麼樣子」就是這些最常見的版型。所以你叫它做任何主題的網頁，它都會無意識地朝這套版型回去。

設計圈把這個現象叫做 AI slop（AI 黏液）——AI 默認生產的、看起來毫無個性的視覺糊狀物。

我接入了一個「AI 味檢測器」

最近 Together AI 發布了一個工具叫 hallmark，它就是專門當 AI slop 的對抗劑。它做的事很單純：列出 69 道「AI 味閘門」（gate），任何網頁設計只要踩到一條就被點名。

例子：

  • 用紫色漸層 hero → 點名
  • 字體選 Inter 又當 display 又當 body → 點名
  • 三欄等寬 feature 卡 → 點名
  • 重繪假的瀏覽器框 / 假的手機殼裝飾 → 點名
  • 動畫用瀏覽器預設的 ease 曲線而不命名 → 點名

它的核心立場是：結構多樣性比視覺多樣性更重要。兩個網頁就算配色不同，但結構都是「大標 + 三欄 + CTA」這套，那就是同一張模板換顏色而已。它要求你動結構，不是動色票。

整合姿勢：事前提醒 + 事後檢查

我把 hallmark 接進我自己的 /output-html 流程。/output-html 是一個會把我的筆記寫成可分享 HTML 頁面的工作流。整合姿勢是「雙閘門」。

事前提醒——當流程要呼叫另一個 UI 工具（叫 ui-ux-pro-max，一個內建 67 種設計樣式可選的 UI 助理）幫我寫程式時，我會在指令裡塞一段約束：「所有顏色、字體都要透過 CSS 變數使用，不准寫死；不准重繪假的瀏覽器框；不准編造數字。」這條叫 token discipline（樣式變數紀律），目的是讓上游一開始就不要違規。

事後檢查——流程跑完、HTML 寫出來後，再呼叫 hallmark 跑一次 audit（掃描）。它會掃 HTML、列出所有踩到 gate 的點。如果掃到嚴重（critical）或重要（major）違規，流程會自動嘗試修兩輪；只剩小違規（minor）就附在輸出後不擋部署。

兩道閘門互補：事前約束讓上游不犯規，事後檢查抓漏網之魚。

中途踩到的坑

整合到一半我以為 hallmark 的 audit 模式會回傳「六軸分數」（哲學、層級、執行、特異性、克制、多樣性各打 0-5 分）。我照這個假設把驗收規則寫進模板，期望「任一軸 < 3 就視為失敗」。

寫完之後我才仔細讀 hallmark 的 verb（功能模式）規格文件。

它的 audit 模式不執行六軸打分。六軸打分只在它「主動生成新設計」時跑，叫 pre-emit critique（送出前自評）。audit 是純診斷工具，只列違規清單、不打分。

這個錯位的根因是我看主檔的描述就動手。主檔說它有六軸打分能力，但能力是綁在生成模式上，不是 audit 模式。教訓：整合外部工具前要讀清楚對方各個功能模式的規格，不能憑主檔印象。

真正划算的做法是修「模板」

整合做到第二天我注意到一件事。我的 HTML 輸出有兩條通路：

  1. 我自己在 Claude Code 跑 /output-html（主流程）
  2. 我從 Telegram 透過一個叫 Hermes 的機器人觸發（旁路）

Hermes 那條因為設計選擇，刻意繞過完整 skill 流程——它只讓 Claude 做翻譯加結構化，其他全用 Python 確定性處理。我剛剛改的 skill 流程，Hermes 完全不會經過。

但兩條通路都用同一份 HTML 模板（叫 KB-02）。我 audit 一個既有頁面後，發現模板本身踩了三條 minor：字體沒透過 CSS 變數、進度條動畫改變 width 而不是用 transform、沒命名 easing 的轉場曲線。

結論很明顯：與其在 Hermes 那條另外加 audit（會增加延遲、跑一個 LLM subprocess、破壞它的確定性），不如直接修模板。

模板修一次，兩條通路下次產出的 HTML 自動就是 hallmark-clean。

這是「上游精度優於下游檢驗」這條精密機械工程的老原則，在這裡再次驗證——修源頭永遠比加檢查網划算。後來我又用同樣邏輯修了另一份簡報模板（KB-05）的四個 minor。

結語

hallmark 跟我原本用的 ui-ux-pro-max 之間，常有人以為它們在競爭。其實不是。前者是「擋掉什麼」（69 道閘門），後者是「能做什麼」（67 種樣式選單）。最佳姿勢是兩個一起用：ui-ux-pro-max 選你想要的風格，hallmark 把 AI 味擋下來。

放大來看，這條邏輯適用於任何 AI 協作場景：很多 AI 的價值不在於它能生產什麼，而在於它能不能識別並拒絕自己的預設輸出。能拒絕自己的 AI，才能跟人類產生真正的合作。只會堆疊預設的 AI，只是更快版本的 stackoverflow。
