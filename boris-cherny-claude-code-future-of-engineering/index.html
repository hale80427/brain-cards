Boris Cherny 談 Claude Code：工程師的下一個抽象層

BLUF Claude Code 不只是「寫程式更快」的工具。Anthropic 的 Boris Cherny 在這支訪談中說：工程師的工作正往更高一層的抽象跳——從自己寫程式，到讓 AI 替你跑 agent loop（自動化任務循環）。組織也該跟著變：少配人手、多給每人 token 預算，逼出自動化。工程師的核心能力，會從「會寫程式」轉向「能設計可持續運轉的流程」。

這是 Boris Cherny 在 WorkOS 主辦的 Acquired Unplugged 節目中的訪談。Boris 是 Claude Code 的主要創造者，任職於 Anthropic（研發 Claude AI 的公司）。

用一段話說清楚

Claude Code（讓 AI 替你自動寫程式的工具）背後藏著一個更大的觀點。

Boris 說：工程師的工作正往更高一層的抽象跳。從自己打每一行 code，到讓 AI 替你管理 AI，再到寫能自動跑的 agent loop（自動化任務循環）。

組織形態也跟著改變——不再只靠增加人手，而是給每個人更多 token（AI 的計算資源），讓重複的事自動化。

工程師的工作怎麼一直在變？

Boris 把工程歷史看成一條「愈來愈少親手動工」的路。每個時代，工程師都往更高一層的抽象跳。

Boris 說，他現在不再主要靠自己 prompt（下指令給）Claude 寫程式。他在寫 loop——讓 loop 自己去問 Claude、判斷下一步要做什麼。

Claude Code 怎麼來的？

Claude Code 源自 Anthropic 的 Labs 原型團隊，任務是找「下一個大產品」，也要把模型能力推到真實使用場景。

為什麼從 coding（寫程式）切入？因為程式有明確的對錯訊號：能跑就是能跑，會報錯就是報錯。這讓 AI 安全研究者可以在「真實使用」中觀察模型行為，比在實驗室裡測試更有意義。

Anthropic 內部的變化

Boris 說，Anthropic 曾公開表示「每位工程師的程式產出約增加 3 倍」，但他說那已過時，現在更高。

更有趣的是新人入職的改變。以前要花好幾週熟悉 codebase（程式庫）。現在的做法是直接在程式庫裡問 Claude，甚至有人做了能直接查資料庫的 skill（功能模組）。

「新人入職，ramp-up（熟悉上手）時間大概只要兩天。」— Boris Cherny

什麼是 generalist builder？

Claude Code 的招聘偏好 generalist（通才型建造者）。Boris 描述的日常是：一個人可能同一天談使用者需求、規劃範疇、設計介面、拉資料、建 dashboard（儀表板）。

這不是「什麼都會一點」的意思。而是 AI 工具把中間的執行成本壓低，讓一個人能從問題一路走到驗證，端到端負責。

「我們開始看到所有角色融合，慢慢變成一種 builder（建造者）。」— Boris Cherny

給公司的建議：多 tokens、少人力

Boris 的建議很直接：給每個員工足夠多的 token（AI 計算資源）讓他們實驗，然後故意少配人手。

邏輯是：人手少了，團隊就被迫把重複工作寫成工具或 loop，讓 AI 自動跑。前期建置成本可能較高，但後續每次執行同樣任務的成本持續下降。

注意：這個建議不適用所有場景。法務、醫療、財務決策等高風險領域，不能直接套「少人 + 多 tokens」的邏輯。版本控制、測試和審核機制是必要配套。

品味也會被 AI 吃掉？

Boris 用自己舉例：他偏好 functional programming（函數式寫法），不想在 codebase 裡看到 class（物件導向的基本結構單位）。

後來模型開始寫 class，商業結果更快達成，程式品質也不差。他就承認，那只是個人偏好，不是普世真理。

他進一步說：如果 AI 能讀 Twitter 回饋、GitHub issues、Slack 訊息並提出產品方向，那人類對「product taste（產品品味）」的優勢，半衰期可能也不長。

「我們最後要教模型的，可能是 values（價值觀）——就像教孩子成為好人一樣。」— Boris Cherny

可以馬上試的 5 件事

  • 找一個重複任務，要求負責人不只交付結果，還要交付可重跑的 script（腳本）或 loop。
  • 對新人入職做 A/B 測試：傳統文件 vs. 直接問 AI，量測到第一次有效 PR（程式提交）的時間。
  • 設計 token budget（AI 使用預算），記錄「這次 token 換掉了哪段人力工時」。
  • 把職能交界的任務交給小型通才團隊，不走一關一關傳遞的流程。
  • 對 agent loop 加入 review gate（審核關卡）：測試、diff（差異比對）、rollback（回滾）機制。
