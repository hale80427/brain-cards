Boris Cherny 談 Claude Code 與工程師的未來

BLUF Claude Code 主工程師 Boris Cherny 說，工程師的下一步不是「更快寫程式」，而是設計讓 AI 自動跑的迴圈。他給企業的建議：刻意少配人力、多給 tokens（AI 使用量），逼出真正的自動化習慣，才能讓每個人做更多事。文末附可操作 checklist。

這篇整理來自 WorkOS 的訪談節目「Acquired Unplugged」，主講者是 Claude Code（一個能幫你寫程式的 AI 工具）的核心工程師 Boris Cherny。點這裡看原始影片。

Claude Code 怎麼來的？

Claude Code 起於 Anthropic Labs，也就是公司裡負責「找下一個大產品」的原型小組。

Boris 說，當時 AI 的核心模型已經很強，但市面上還沒有產品能把這個能力完整承接下來。

為什麼從 coding（寫程式）切入？有兩個原因：

  • 程式有明確的對錯：能編譯（compile）、測試通過就是成功，讓研究 AI 行為更準確。
  • 讓 AI 寫程式，就是讓 AI 直接跟真實世界互動，這對 AI safety（AI 安全研究）也有幫助。

讓 AI 寫更多程式的關鍵不是介面，是模型本身

很多人以為，要讓 AI 工具更好用，就要做更漂亮的 UI（使用者介面）。Boris 直接點破：

「每次讓我感覺模型寫了更多程式，真正的原因就是——模型變強了。」

命令列、桌面 app、Slack 機器人這些工具層確實有用，讓不同習慣的人更容易接觸 AI。

但能委派給 AI 的工作上限，還是取決於模型本身有多強。

Anthropic 內部怎麼用：新人兩天就上手

Anthropic 全公司都在用 Claude Code，包括做模型研究的科學家。Boris 提到兩個數字：

  • 每位工程師的程式碼產出提高了大約 3 倍（他說這已是過時的公開數字，現在更高）。
  • 新人的熟悉期從過去幾週，縮短到大約兩天。

原因是公司知識從「藏在人腦和舊文件裡」，變成「可以直接問 AI 的工具」。

新人不再需要翻文件、問資深同事，直接在程式碼庫（codebase）裡問 Claude 就好。

工程師下一步做什麼？設計讓 AI 自動跑的迴圈

Boris 說，程式設計的抽象層一直在上升：從打孔卡到組合語言（assembly），從 Python 到 IDE（整合開發環境）加自動補全，再到 Claude Code。

而他目前的工作，又更進一步：

「我在跑迴圈（loops）。是迴圈在主動問 Claude 要做什麼，不是我在問。」

白話說：他在設計一套自動化系統，讓系統自己找 AI 問問題、自己判斷下一步。

這是影片最重要的工程觀點：未來工程師的工作單元，可能不是「一段程式碼」，而是「一個持續自動運轉的 AI 迴圈」。

角色正在融合：從分工到全程建造

傳統公司的需求，要從產品、設計師、工程師、資料科學家一棒一棒傳下去。Boris 說這條接力路正在消失：

「我們開始看到所有角色融合、熔化成一個——建造者（builder）。」

這不是說人人都要樣樣精通。而是「能把問題一路帶到驗證結果」，比「我只負責哪一段」更重要。

傳統流程 AI 時代趨勢
PM → 設計師 → 工程師 → 測試，分段接力 一個人從問題談到驗證結果
遇到瓶頸就加人 少配人力 + 多給 tokens，逼出自動化
新人幾週才能熟悉環境 直接問 AI，兩天上手

非工程師也來了：強到肯自己裝 Node.js

Claude Co-work 是 Claude Code 的延伸，讓不想開終端機（terminal）的人也能用 AI 的完整能力。

背後有個訊號：有資料科學家、非工程師為了用 Claude Code，願意自己學終端機、裝 Node.js（一種程式執行環境）。

他們甚至願意自己設 API 金鑰（存取 AI 服務的密碼），來連上 Claude。

「當需求強到使用者願意忍受這麼高的門檻，就是該把它做成大眾化產品的時機。」

給企業主的建議：少配人力，多給 tokens

「給每個人盡可能多的 tokens（AI 使用量）。」「什麼都少配一點人力。」

背後的邏輯：人力稀少時，團隊會被迫把重複工作寫成工具或自動迴圈。

Tokens 比人力便宜，試錯也快。前期可能麻煩，但下一次做同樣的事，成本大幅下降。

注意：這個建議適合軟體、資料、內部工具等可自動驗證的任務。法務、醫療、財務決策等高風險場景需謹慎，並配套測試、版本記錄、可回滾等機制。

品味也會被 AI 吃掉一半？

Boris 承認，他過去很堅持 functional programming（一種避免使用 class 的程式風格）。

但模型開始寫有 class 的程式，商業成果反而更快，品質也不差。他說：

「我意識到，我的品味，可能只是個人偏好而已。」

他進一步說，當模型能讀 Twitter 回饋、GitHub 討論、Slack 訊息並提出產品方向，連「產品品味」這個優勢也可能慢慢被壓縮。

最後他說，人類最終要教給模型的，可能是 values（價值觀）——就像教孩子成為好人一樣。

可以現在開始做的五件事

  • 找一個重複做的任務，要求負責人不只交結果，還要交一個「可重跑的腳本」。
  • 對新人 onboarding 做對照實驗：傳統文件 vs 直接問 AI，看誰先出第一個有效貢獻。
  • 設計 token 預算：不只設上限，也記錄「這次 AI 幫你省掉哪段人力」。
  • 把跨職能的任務交給小型 generalist 團隊，不要走 PM → 設計師 → 工程師的接力模式。
  • AI 自動迴圈要加驗收關卡：測試、版本記錄、權限、可回滾，不要只追速度。
